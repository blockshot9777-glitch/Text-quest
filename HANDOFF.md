# ПЕРЕДАЧА ПРОЕКТА В CURSOR

Симулятор выживания: физика, снаряжение, общество, генератор миров под любой
сеттинг, движок хода, локальное окно с выбором ЛЛМ. Собрано и проверено в
чате с Claude; дальнейшая работа — в Cursor.

---

## 0. ЗОЛОТОЕ ПРАВИЛО — прочитать первым

**Никогда не доверяй сообщению об успехе. Проверяй фактически: запуск, grep,
тест.** За время сборки этого проекта было найдено больше пятнадцати
дефектов, из них не меньше пяти — тихо провалившиеся строковые замены
(`str.replace()` в Python не бросает ошибку, если строка не найдена, просто
возвращает текст без изменений). Три раза это давало код, который выглядел
переписанным, а на деле остался старым.

Практическое следствие для Cursor: после любой правки —
1. `grep` на то, что должно было исчезть;
2. `python3 selftest.py` — весь набор, не выборочно;
3. полный путь исполнения, а не только «безопасная» ветка (пример: self-test
   валил механоида только через `look`, которая не делает бросков — баг в
   `condition_factor()` жил там незамеченным, пока проверку не заставили
   дойти до `--check`).

Если правишь код через `str.replace()` или похожий поиск-замену — всегда
`assert новая_строка in результат` перед записью файла.

## 1. КАРТА ФАЙЛОВ

### Ядро (можно редактировать по отдельности при разработке)
| Файл | Роль |
|---|---|
| `engine.py` | ход: время по сегментам, среда, потребности, броски, доступ к вещам, бой, лечение, snapshot/restore, compact |
| `worldgen.py` | генератор мира из краткого замысла + `validate()` состояния + `validate_ruleset()` |
| `matter.py` | масса/объём/clo любого предмета и одежды из материала и формы; `extend_from_rules()` — материалы из данных |
| `edc.py` | попаданец из наших дней (только XXI век): момент переноса → одежда/карманы. Другие эпохи — worn/items в замысле, не этот модуль |
| `society.py` | NPC встречаются, слухи расходятся каналами, фракции воюют, ресурсы площадок расходуются — без участия игрока |
| `ruleset.json` | ВСЁ содержимое человека: потребности, симптомы, пороги, навыки, модификаторы условий, последствия провала, cold_model, healing. Код их не знает — только читает |
| `ruleset_mech.json` | тот же движок, другое существо (механоид) — доказательство универсальности |

### Сборка (не редактировать руками — пересобираются)

| `play.py` | локальный сервер + окно в браузере + оркестратор ЛЛМ (два вызова на ход) |

### Рабочие состояния (примеры, не часть движка)
`rimworld2.json`, `kastor.json`, `novgorod_1052.json`, `gory.json`,
`state_start.json` — сгенерированные миры для трёх сеттингов из разговора.
`brief_*.json` — замыслы, из которых они собраны.
`brief_jurassic.json` / `run_jurassic_random.py` — попаданец из XXI в поздней юре,
seed `150145000`. Прогон на 1000: `python examples/run_jurassic_random.py 1000`.
Харнесс берёт одно действие по нужде (не четыре равных слота): без боя,
без зажигалки, без материала не из данных. После наполнения тары по тегу:
смерть на 690-м от голода 100 (жажда 47), t_h ≈ 348. Два заслона, 20 снов,
138 питья, 81 добыча, отказов 0. Огонь 0 — контракт. Дыра «пустые порции
заняли руки, take не наполняет» закрыта. Умер в челноке отмель↔поляна:
после «Запах падали» охотник на отмели, к туше харнесс не идёт —
`RISK_APPROACH_HOSTILE = False` (булев, не шкала), предел стратегии, не дыра выдачи еды.

## 2. ПОРЯДОК РАЗРАБОТКИ

Порядок правки фич — [FEATURE_GUIDE.md](FEATURE_GUIDE.md): тип задачи,
тег вместо имени, двусторонняя проверка, атомарность, чек-лист после правки.
Один коммит — один тип изменения; `ruleset.json` не трогать «заодно».

Правь только файлы из «Ядра». После правки:

```bash
python3 audit.py                       # статическая ревизия — до тестов
python3 selftest.py                    # должно быть «провалено 0»
python3 build_bundle.py                # пересобрать sim.py
python3 sim.py selftest                # проверить сборку отдельно
```

Если меняешь `ruleset.json` — дополнительно:
```bash
python3 worldgen.py checkrules --rules ruleset.json
```

Если меняешь схему состояния — проверь все существующие миры:
```bash
for f in rimworld2.json kastor.json novgorod_1052.json gory.json; do
  python3 worldgen.py check --state $f
done
```

## 3. АРХИТЕКТУРНЫЕ РЕШЕНИЯ, КОТОРЫЕ НЕЛЬЗЯ ОТКАТЫВАТЬ НЕЗАМЕТНО

Если Cursor (или ты) захочет «упростить» что-то из этого — сначала перечитай
почему оно так сделано:

- **Состояние — файл, не память модели.** Вся физика и потребности живут в
  JSON, движок читает и пишет его. Модель никогда не считает сама.
- **`ruleset.json` — единственный источник содержимого для существа.**
  Потребности, симптомы, пороги смерти, модификаторы — не в коде. Это то,
  что даёт «универсальность на 99%»: механоид работает на том же `engine.py`.
- **Материалы/формы можно доопределять из `ruleset.json`** через
  `extend_from_rules()` — экзотика сеттинга не требует правки `matter.py`.
- **Раны обобщены через `ruleset.json → wound_model`**: какое витальное поле
  принимает кровотечение (`bleed_target`) и инфекцию (`infection_target`) —
  не зашито в `engine.py`. У механоида это может быть не `blood_loss_pct`,
  а что-то своё. Проверять `ruleset_mech.json → wound_model` при правках.
- **RNG только через `hashlib.sha256(seed|turn|индекс)`.** Встроенный
  `hash()` рандомизирован между процессами Python — уже ловили баг на этом.
- **Не больше двух проверок за ход** (`resolution.max_checks_per_turn`) —
  иначе катастрофы накапливаются быстрее, чем задумано (было посчитано:
  93% смертей за 50 ходов при трёх проверках вместо двух).
- **Катастрофа не может убить там, где действие не смертельно** —
  `consequence()` разграничивает бытовой провал и смертельный риск.
- **Игрок не видит ни одного числа.** В `play.py` это гарантировано физически:
  второй вызов модели (проза) получает только текстовые симптомы и метки
  исходов, JSON состояния в браузер не попадает вообще.
- **`_make_item` в worldgen — прокси, не копия `make_item`.** Тело живёт в
  `matter.py`; обёртка только `getattr` + вызов, иначе смена сигнатуры
  разойдётся тихо (`grep matter\\.` его уже не найдёт).
- **`PHYSICS_ON` — публичное имя бандла.** `play.py` читает `sim.PHYSICS_ON`.
  Минификация/переименование глобалей в `build_bundle.py` сломает схему
  так же тихо, как когда-то `matter.make_item`.
- **Формы `skills` в `normalize_brief` исчерпывающие:** объект `{имя: число}`;
  список `{name, value|level|score}`; список одноключевых. `rating` — отказ.
  Список ключей — `SKILL_LIST_VALUE_KEYS`, не догадка в `.get()` цепочке.
- **Переход на несуществующую площадку отклоняется**, а не тихо создаётся —
  это граница «известного», площадку должен сгенерировать рассказчик/агент
  осознанно, добавив её в `sites_canon` перед `--to`.
- **Счётчик: `payoff` — фраза в журнале, `on_complete` — мутация состояния.**
  Таймер без `on_complete` срабатывает только строкой (валидатор предупреждает,
  не молчит). Операции общие (`site`/`sites` + `env`, либо `path` + `set`/`add`).
  Гарантии, которые стоит не путать:
  - **Один счётчик срабатывает один раз за жизнь** — флаг `fired`. Откат
    `filled` ниже `max` (compact, ручная правка, старое сохранение) не
    переигрывает `on_complete`. Переход `before < max` сам по себе этой
    гарантии не даёт.
  - **`add` не идемпотентен и не обязан быть.** Это выбор автора данных, не
    пробел движка. `set` безопасен повтором; два счётчика с `add` на одно
    поле складываются. Удвоение — читать замысел, не чинить ядро. Валидатор
    предупреждает, если такие `add` пересеклись.
  - **`sites: "*"` — снимок `sites_canon` на момент срабатывания**, и только
    у тех, у кого уже есть `env`. Площадка, которой ещё не было (граница
    известного) или которую `compact` выбросил и потом вернули из сида,
    прошедшее событие не наследует: игрок ту стадию не застал. Отложенного
    применения нет.
  - **Порядок в часе фиксирован:** `tick_clocks` → `recompute_env` → нужды
    и холод этого часа. Сработавший счётчик уже влияет на этот же час, а не
    «после всех часов акта». Следствие: `on_complete` не видит уже
    пересчитанную среду часа («если в отсеке было холоднее X — ещё эффект»).
    Такое исключение требует явного второго прохода, а не сдвига одной строки.
- **Ресурс площадки → предмет.** `--take-resource имя:количество` сначала
  ищет в доступе предмет с пересечением тегов ресурса и `fill < 1` и
  наполняет его (сколько влезает и сколько есть на площадке). Новый предмет
  через `matter.py` — только если такой тары нет. Отказ до списания
  `resources[].amount`, если класть некуда и наполнять нечего. Не по имени
  «фляга» и не отдельным `--recharge`. `--water` / `--food` без предмета
  нужду не закрывают (списывают `fill` по тегам из `item_use.water_tags` /
  `food_tags`); пустая фляга (`fill=0`) — `ОТКАЗ`, ход не идёт.
  `charge_pct` у предмета в руках падает на `item_use.charge_per_h`.
  Не зашито под «Релей».
- **`--water` / `--food` — синонимы CLI, не словарь ядра.** Списывают предметы
  по `item_use.water_tags` / `food_tags` и восполняют нужду с тем же
  `recovers_by`. Флаги необязательны (`default=0`): механоид без этих тегов
  ходит без них; переданный `--water` без `water_tags` — отказ. Будущий
  `--recharge` — новый синоним в другом наборе правил, не расширение этих флагов.
- **Огонь жрёт топливо.** `--fire` без запаса с тегом из `item_use.fuel_tags`
  или без зажигателя (`igniter_tags`, обычно «огонь») — отказ до тика.
  `site.hearth` снимает требование зажигателя (очаг в данных площадки), топливо
  всё равно списывается по `fuel_per_h` кг/ч. Имя предмета ничего не значит:
  «спирт» без тега — просто ресурс. То же для питья и еды: «кипяток»/«хлеб»
  без тега из `water_tags`/`food_tags` не пьются и не едятся. Теги задаёт
  замысел и `item_use`, не ядро. Двусторонняя проверка: чужие теги работают,
  привычные человеческие слова без объявления в *этом* наборе — отказ.
  `site.shelter` даёт штиль без флага `--sheltered`.
- **`edc.py` знает только карман XXI века.** `worldgen.expand` зовёт его
  исключительно при `carryover`. Не учить модуль «ещё и другим эпохам»:
  остальные сеттинги задают `worn`/`containers`/`items` сами или через `loadout`.
- **Промпт генератора может показывать примеры тегов.** Ядро не знает «спирт».
  `SYS_BRIEF` в `play.py` имеет право дать образец `item_use` и `resources[].tags`,
  чтобы автор замысла не изобретал словарь с нуля. Подсказка живёт в промпте, не в движке.
- **`unconscious` не пауза.** Действия игрока — отказ; время тикает. В 4 °C
  без огня `cold_stress`/`core_temp` доводят до `dead`. Выход в `alive`, если
  ядро поднялось до `vitals.core_temp_c.recover_above` (32). Это не
  `incapacitated` из markdown.
- **Стресс 1000 ходов «Релей»** (`python examples/run_drift_random.py 1000`,
  seed `55020714`): смотреть сводку `examples/run_drift_summary.json`. Пустая
  фляга больше не пьётся. Зажигалка и спирт для горелки — расходный огонь.
  На текущей политике после правки топливо берётся и сжигается; смерть на
  130-м уже от жажды, не от `unconscious` в 4 °C без огня.
- **Стресс юра 1000 ходов** (`python examples/run_jurassic_random.py 1000`,
  seed `150145000`): сводка `examples/run_jurassic_summary.json`. Осмысленный
  выбор, не RNG. Два заслона из объектов с `parts`. Все счётчики с `on_complete`
  дошли до `max`. После наполнения тары: смерть на 690-м от голода, не
  жажды у пустых порций. Питьё 138, добыча 81, отказов 0. Бой исключён.
  Огонь не выдуман. К врагу не подходит: голод при охраняемой туше —
  предел стратегии, не дыра `take`/еды.
- **Конструкции.** `structure_use` в наборе правил: теги ролей, часы из
  объёма. `--build` / `--break` / `--reveal` атомарны. `--break` снимает
  конструкцию целиком: роль на тегах, не на «крыше» или «стене». Снять
  одну часть из трёх — нет команды (не тихий баг). Проза без `parts` не
  ломается. `player_made` переживает повторный `compact`. Заявленная
  масса vs части: `mass_matches_parts` — 50 г или 5%, что больше.
  Имена построек в ядро не класть.

## 4. ЧТО НЕ РЕАЛИЗОВАНО (честный список)

По убыванию ценности:

1. **Ремесло носимых вещей.** Конструкции площадки (`--build`/`--break`) уже
   есть. Изготовление ножа в руках из тех же частей — ещё нет. Порог
   `raw < 5` без броска — баланс ремонта, не дыра. Снять одну часть из
   нескольких (`--break-part`) — тоже нет: роль не умеет «пропасть с крышей
   и остаться со стенами».
2. **`--drop`.** Наполнение тары по тегу уже в `take`. Явный выброс нужен,
   когда руки и вся тара заняты предметами *без* совпадающего тега (или
   полными): набрать новый ресурс некуда. Эту юрскую смерть закрыло
   наполнение, не drop. Не добавлять, пока прогон не умрёт именно так.
3. **Палатка как носимый предмет.** Укрытие площадки — `site.shelter` /
   `--sheltered`. Свой тент, который ставишь на ветру, ещё не предмет.
4. **Смена сезонов.** Календарь их знает (`calendar.seasons`), но год не
   идёт — только сутки через `time.t_h`.
5. **NPC не голодают и не болеют** — потребности есть только у игрока.
   `ruleset.json` для этого уже universal-ready, просто не подключено к NPC.
6. **`take_resource` / `parts` всё ещё склеенные строки** (`"имя:кол-во"`,
   `"материал:форма:Д:Ш:В"`). `checks` уже объекты + одна закрытая
   строковая форма; эти два поля — тот же класс, отложены явно, не забыты.
   Если каждое поле лечится одним и тем же нормализатором — сигнал, что
   CLI движка когда-нибудь стоит перевести на структурированный ввод
   везде одинаково. Не сейчас и не поле за полем «заодно».
   Разбор хода уже: `mech_schema(S)` на каждый ход (навыки/выходы/домены
   из состояния), `normalize_intent`, отказ на `minutes < 0` вместо
   `max(0, …)`. Потолок абсурда `MECH_MINUTES_CEILING` не заводили:
   нет живого прогона с `1e9`. Верх `minutes` — физика хода, не форма.
7. **UI `play.py` без сохранения/отката из окна** — `snapshot`/`restore` есть
   в движке, кнопки в браузере нет.
8. **Длинный переход (режим ПЕРЕХОДА).** `tick()` всегда идёт по часам;
   недели межпланетного дрейфа — тысячи итераций в одном `--minutes`.
   Прогон на 1000 **ходов** (часы, не месяцы) эту дыру не закрыл.
9. **Статус `incapacitated`.** В markdown есть, в `death_check` — `alive` /
   `unconscious` / `dead`. Бессознательный уже не замирает навечно в холоде.
10. **`llm()` в `play.py` не потоковый.** Ollama шлёт `"stream": false`,
    OpenAI-совместимые (LM Studio) — тоже; `urllib.request.urlopen` ждёт
    тело целиком. Зацикленную генерацию (кривая кавычка → повтор
    `" :", " ,"` до `max_tokens`, живой прогон капсулы ~127 с) нельзя
    оборвать раньше потолка, только распознать постфактум
    (`detect_degenerate_loop`). Ранняя остановка — отдельная работа:
    SSE-разбор ответа. Не путать с обрывом по объёму: тот лечится
    компактнее, цикл — нет.

## 5. ЕСЛИ НАЧИНАЕШЬ НОВУЮ СЕССИЮ В CURSOR

Скорми модели в Cursor:
1. Этот файл, `FEATURE_GUIDE.md`. Если работа про стройку — ещё `BUILDING_NOTES.md`.

локально проще всего: `ollama serve`, любая модель через `ollama pull`).
